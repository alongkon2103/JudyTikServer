# โหมดการเล่น Soundpad

แต่ละรายการรองรับ `playMode` สามค่า:

- `restart`: กดซ้ำเพื่อตัดเสียงเก่าแล้วเริ่มใหม่ เป็นค่าเริ่มต้นของโปรแกรมใหม่
- `hold`: กดค้างเพื่อเล่น ปล่อยเพื่อหยุด
- `toggle`: กดเพื่อเล่น กดอีกครั้งเพื่อหยุด

ใช้กับปุ่มในหน้า Soundpad ปุ่มลัดหน้า Overview และคีย์ลัดที่ตั้งไว้ ไฟล์จบแล้วหยุดตามปกติ ไม่มีการเพิ่มการวนซ้ำอัตโนมัติ

## ความเข้ากันได้ของ API

ใช้ `GET /v1/me/soundpad` และ `PUT /v1/me/soundpad` เดิม เพิ่ม header `x-judytik-soundpad-features: play-modes` เพื่อรับและบันทึก `playMode` ในรายการแต่ละปุ่ม ฟิลด์นี้ไม่บังคับ โปรแกรมใหม่ถือว่าค่าที่หายไปเป็น `restart`

ไคลเอนต์เก่าที่ไม่ส่ง header จะไม่ได้รับฟิลด์ใหม่ และเมื่อบันทึกรายการเดิม เซิร์ฟเวอร์รักษาโหมดที่ตั้งไว้ตาม ID ของปุ่ม โปรแกรมเก่ายังคงใช้พฤติกรรมการเล่นของเวอร์ชันนั้น ไคลเอนต์ใหม่ที่ส่ง header สามารถล้างโหมดกลับค่าเริ่มต้นโดยไม่ส่งฟิลด์นี้ ต้องส่ง revision/precondition ตาม API เดิม

การเปลี่ยนแปลง Soundpad รอบนี้ไม่มี migration, grants หรือ dependencies ใหม่ ให้ build และ restart backend หลัง pull ตามขั้นตอนเดิม

## การตรวจสอบ

ทดสอบ validation ทั้งสามค่า การอ่าน/บันทึก การรองรับไคลเอนต์เก่า และฐานข้อมูลจริงสำหรับการรักษาโหมด ปุ่มและคีย์ลัดทดสอบการกดรัว ปล่อยก่อนโหลดเสียงสำเร็จ ย้ายโฟกัส และเปลี่ยนบัญชี โดยไม่ให้คำสั่งเก่าหยุดเสียงของการกดใหม่
