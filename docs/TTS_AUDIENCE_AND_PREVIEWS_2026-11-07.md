# กลุ่มผู้ฟัง TTS ชื่อช่อง และพรีวิว Overlay

- TTS เลือกอ่านคอมเมนต์จากทุกคน หรือกลุ่มผู้ติดตาม สมาชิก/ผู้สมัครสมาชิก ผู้ดูแล แฟนคลับตามเลเวล ผู้ส่งของขวัญตามเลเวล และผู้ส่งของขวัญอันดับต้นของไลฟ์ที่โปรแกรมรับอยู่ เลือกหลายกลุ่มเป็นเงื่อนไข OR
- เลเวลแฟนคลับแยกจากเลเวลผู้ส่งของขวัญ ไม่เดาสิทธิ์เมื่ออีเวนต์ไม่มีข้อมูลยืนยัน ใช้ badge/follow metadata และอีเวนต์ follow/subscribe/fanclub ที่รับจริง คิวข้อความทดสอบและเสียงที่เรียกจาก Actions ยังใช้ได้ตามเดิม
- อันดับผู้ส่งของขวัญใช้เหรียญที่ได้รับระหว่างเชื่อมต่อไลฟ์นี้ คิดตาม gift delta ไม่บวกคอมโบตอนจบซ้ำ จำสถานะระหว่าง reconnect ห้องเดิม และเริ่มใหม่เมื่อ room ID เปลี่ยน
- ชื่อช่องบันทึกลงไฟล์บนเครื่องแยกบัญชี แม้ปิดการเชื่อมต่ออัตโนมัติ บันทึกเมื่อหยุดพิมพ์/ออกจากช่อง/กดเชื่อมต่อ และโหลดกลับเมื่อเปิดโปรแกรมใหม่
- WIN ค่าเริ่มต้นเป็น 0 / 10 ตัวเลขขนาดเท่ากัน Komika Axis สีเขียว–ขาว พื้นหลังโปร่งใส ไม่แสดงป้าย WIN หรือแถบ progress การเปลี่ยนค่าเริ่มต้นไม่ทับค่าที่ผู้ใช้บันทึกไว้ ใช้ปุ่มคืนค่าเริ่มต้นเพื่อเปลี่ยนชุดเดิม
- พรีวิว Widget และธีมใช้ component เดียวกับ Browser Source พร้อมข้อมูลตัวอย่างที่เปลี่ยนจริง รวมสปิน โหลของขวัญ เวลา อันดับ เป้าหมาย และ Slider ส่วน WIN/Spin WIN มีตัวอย่างเคลื่อนไหวโดยไม่เปลี่ยนตัวนับหรือรัน Action จริง
- พรีวิวหยุดเมื่ออยู่นอก viewport/ซ่อนหน้า/ผู้ใช้ตั้งลดการเคลื่อนไหว และไม่เปิด canvas physics สำหรับโหลตัวอย่างที่ไม่อยู่บนหน้าจอ

## Server

ต้องอัปเดต Server เพื่อบันทึกกลุ่มผู้ฟัง TTS ใหม่ ไม่มี migration หรือ environment variable เพิ่ม

Client ใหม่ส่ง `x-judytik-tts-features: audience` บน GET/PUT `/v1/me/tts` เพื่อรับฟิลด์ `audience` แบบ optional ฝั่ง Server ไม่ส่งฟิลด์ใหม่ให้ client รุ่นเก่า และเก็บค่า audience เดิมไว้เมื่อรุ่นเก่าบันทึกโดยไม่มีฟิลด์นี้ การคืนค่าเริ่มต้นส่งค่า everyone อย่างชัดเจน

```powershell
Set-Location C:\JudyTikServer
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Pull ไม่สำเร็จ' }
npm --prefix server run build
if ($LASTEXITCODE -ne 0) { throw 'Build ไม่ผ่าน' }
pm2 restart judytik-backend --update-env
pm2 status
```
